## 二、已经确定的行为规则

1. 每句话都产生声纹判定（可为确认、未知或录音不足）；**只用本轮确认的说话人**自动定位，不能把后来确认的身份倒填到上一句，也不能以“画面里只有一个人”推断说话者。
2. 单一、无否定的“我现在有点热／冷”等舒适请求走本地 `adjust_ac(target=self)`。明确说出的房间优先。自动选房还须满足摄像头人物位置在现有 **3.5 秒**有效期内且房间只有一台目标空调；缺一项就说明缺的是身份、位置还是设备唯一性。
3. 结构化待续请求最多保留 **30 秒**，只记意图、已确认的原说话人和等待项，**不缓存房间或设备**。用户明确回答房间可完成一次；反问位置时，只有原请求和本轮均确认同一人且本轮位置新鲜，才简短回答并接着执行。原请求身份未知时不能自动续做。
4. 取消、新指令、会话结束、超时或发出设备写请求后清除待续。重复回答、插话或结果未确认不得造成第二次写入。没有工具执行结果时，不能把模型的纯文本当作操作成功；操作话术以设备结果为准，报出实际房间和设定值。
5. 对可能未收完整的录音，不凭转写执行设备操作。诊断只记录时长、丢块数量和原因码，不保存音频、转写、姓名或凭据。

## 三、实施任务与进度

### 任务 1：舒适请求与当轮证据

**范围：** `apps/voice-service/src/agent_session.py`、`speaker_identity.py`、必要的 `agent_tools.py` 调用与对应测试。

- [ ] 补本地舒适请求解析：覆盖热／冷及常见口语，拒绝否定、引用、多重或含糊意图；即使模型只返回 `tools=[]`，也由本地决策处理明确请求。
- [ ] 使用本轮结构化声纹、实时人物位置和唯一设备；身份／位置／设备不足分别给出准确澄清。明确房间不走自动选房限制。
- [ ] 内部上下文对已确认声纹使用确定表述；回复中的身份和位置事实重新取本轮证据，不复述旧失败。
- [ ] 最终话术由工具结果生成；区分已确认、未确认、拒绝和未执行。

### 任务 2：一次性待续请求

**范围：** `apps/voice-service/src/agent_session.py` 及对应测试。

- [ ] 增加最长 30 秒的结构化待续状态，不保存旧房间；明确房间回答可完成原请求。
- [ ] 对位置反问只在原请求与本轮确认同一人、且本轮位置新鲜时续做；否则只回答可核实的事实，等待新指令或明确房间。
- [ ] 在取消、替代指令、会话结束、超时和首次写请求后清除状态；重复输入不得再次控制。

### 任务 3：录音完整性与插话

**范围：** `apps/voice-service/src/loop.py`、`barge_in.py`、必要的事件契约及对应测试。

- [ ] 保留约 **0.32 秒**前录，为普通语音结束增加约 **0.16 秒**连续缓冲；分别统计整段录音与有效语音时长，不靠补静音或降低声纹门槛伪造身份。
- [ ] 标记队列溢出、15 秒截断、插话校准期无法恢复的开头及处理阶段切换丢帧；把“可能未收完整”传给设备决策，阻止自动写入。
- [ ] 修正插话判定：不连续语音不能累计成“持续说话”；检查插话与普通采集交接时的音频保留。
- [ ] 仅记录数字时长、丢块数和固定原因码到脱敏诊断。

### 任务 4：模拟验收与真人边界

- [ ] 模拟确认爸爸＋新鲜客厅观察＋“我现在有点热”：恰好一次操作客厅空调，即使模型只返回追问文本也不能绕过本地决策。
- [ ] 模拟身份未知、观察过期、设备不唯一：均零写入，提示分别对应真实原因；明确房间按明确目标处理。
- [ ] 模拟同人接续、原说话人未知、明确房间、取消、超时、重复回答、设备未确认：无重复写入，无“未执行却说成功”。
- [ ] 模拟短句、停顿、首尾音、队列溢出及插话阶段切换；确认残缺录音不会触发设备写入。
- [ ] 真人麦克风、摄像头、空调效果及声纹准确率由用户手动验收；自动测试通过不能替代实测。
