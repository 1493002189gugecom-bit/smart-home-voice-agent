## 1. 目标

构建一个本机运行的 Unity 虚拟全屋空间：显示人物与设备，真实麦克风接收语音，真实摄像头检测人物，由 Agent 结合意图、模拟位置和设备状态调用工具，展示变化并语音反馈。

核心体验是理解自然表达（如“有点热”）和跨房间定向通知（如“叫爸爸和孩子吃饭”），而非游戏玩法或写实建模。

第一版采用唤醒一次、连续对话，不采用完全免唤醒，不要求每句话重复唤醒。

## 2. 已确认的范围与取舍

### 包含
- Unity 桌面小屋，固定厨房、客厅、卧室布局；人物用圆点和名字表示，可手动移动。
- 虚拟灯、空调、室温、各房间播报点。
- 真实语音输入与本地语音输出；支持明确指令、模糊意图、追问以及近期目标承接。
- 真实摄像头人物检测，手动绑定名字；当前说话者由测试者指定。
- 云端文本 LLM 理解意图和选择工具；本地执行与状态校验。
- 本地唤醒检测；唤醒后的连续语音对话；按钮与文字输入作为调试备用。
- 执行记录、模拟设备离线、断线与失败反馈。

### 不包含
- 真实家居设备接入、真实跨房间收音或分区音频播放。
- 人脸/声纹自动认人、根据声纹区分多人、多人同时说话的可靠分离。
- 全屋多摄像头追踪、空间标定、跨镜头重识别、视觉理解复杂行为。
- 完全免唤醒、播放时语音打断、长期习惯学习、自主巡查和定时任务。
- 户型编辑器、角色行走动画、物理温控模拟、写实装修。

最终演进目标是接入真实设备和多摄像头联合空间感知；第一版只保留可替换的适配边界，不预先实现这些子系统。

## 3. 部署与预算

### 本机配置检查
- Windows 11；Ryzen 9 7945HX，16 核 32 线程。
- RTX 4060 Laptop，约 8GB 显存。
- 约 16GB RAM，检查时空闲约 5.9GB；E 盘空闲约 372GB。
- 已有 Python 和 FFmpeg；未安装或基准测试候选模型。

### 基础选型
| 模块 | 设计选择 |
| --- | --- |
| 场景端 | Unity Windows 桌面端 |
| ASR | SenseVoiceSmall ONNX，优先 CPU 量化推理 |
| TTS | Kokoro 中英模型＋sherpa-onnx，优先 CPU |
| 唤醒/VAD | 本地中文唤醒词检测与语音活动检测，不调用云端音频 API |
| 人物检测 | 本地轻量人物检测模型，降低检测帧率并允许配置 |
| Agent | 一个支持中文和工具调用的云端文本 LLM |
| 状态/工具服务 | 本地独立服务，使用 HTTP 与 WebSocket 连接 Unity |

唤醒与检测模型的具体版本、LLM 厂商以及各依赖版本在实现计划的兼容性核验中选择；不改变本设计的行为契约。若找不到满足测试门槛的本地唤醒实现，报告为功能未通过，不擅自用按钮代替正式验收。

第一版只建议购买云端 LLM API。50–100 元为初始试验预算上限建议，不是固定月费或消耗保证。设置厂商预算/告警（若提供），应用侧独立限制请求数、上下文和工具循环；应用限额不能保证厂商账单绝不超额。

不先买服务器、设备、素材或升级内存。32GB RAM 是并行开发时的可选改善，不是运行前提。Unity Personal 使用资格及代码、模型权重、素材许可证在实施前核验；本地运行不等于任意用途免授权。

## 4. 架构与职责

### Unity 展示层
显示全屋、人物、设备、对话与执行结果；提交拖动、模拟温度修改和手动设备操作请求；播放合成音频。不得把本地显示值当成独立权威状态。

### 本地感知与语音服务
处理麦克风、唤醒、VAD、ASR、摄像头检测、TTS。对外输出带来源与时间的事件；不决定家居操作。音视频采集采用唯一采集入口，其他模块消费帧/音频，避免多个进程争抢设备。

### 家庭状态服务
唯一权威状态来源，维护房间、人物、设备和版本；接受 Unity 与工具层的受控更新，向 Unity 推送状态。可独立于渲染和模型测试。

### Agent 编排层
接收文字、来源房间、测试说话者和有限对话上下文，查询状态，调用受限工具或追问。管理超时、每轮调用上限、取消与澄清状态。

### 工具执行层
验证对象、参数、权限和状态版本；更新虚拟设备或建立播报任务；提供操作编号与明确结果。LLM 无任意代码执行、数据库写入或主机控制权限。

各层是职责边界，不要求每层都成为单独进程或网络服务；首版避免微服务化。

## 5. 状态与感知边界

### 核心对象
- 房间：稳定 ID、名称、模拟室温、设备列表。
- 人物：稳定 ID、显示名、家庭称呼映射、模拟房间/坐标。
- 视觉观察：摄像头 ID、临时轨迹 ID、框、检测置信度、观察时间、手动身份绑定。
- 设备：稳定 ID、房间、类型、状态、在线标志、版本。
- 对话：会话 ID、测试说话者、来源收音点、近期目标、待澄清请求、最近活动时间。
- 操作：请求/操作 ID、目标、参数、状态、错误、状态版本与时间。

### 位置与身份
- 全屋人物位置以手动模拟为准，摄像头观察不覆盖模拟位置。
- 检测置信度不是身份置信度；手动身份绑定不冒充自动识别结果。
- 摄像头临时轨迹丢失时解除绑定，重新出现不自动认作原人。
- 摄像头看见某个人，不意味着该人正在说话；第一版不做自动视听说话者关联。
- 界面分别标明“模拟位置”“摄像头检测”“手动绑定”“测试说话者”。
- 唤醒词不是身份认证；第一版只控制无实际物理风险的虚拟设备。

### 设备语义
灯包含开关和 0–100 的亮度；空调包含开关、模式、目标温度。允许温度上下限和默认舒适温度来自本地配置，不由 LLM 发明。

模拟室温与空调目标温度独立。调低设定不立即改变室温；首版由测试面板修改室温，不模拟热力学过程。

## 6. 语音会话状态机

1. **静音**：释放或停止麦克风采集，界面明确提示；由用户显式开启监听。
2. **待机**：持续本地唤醒检测，不将普通聊天上传云端，不做持续全文 ASR。
3. **已唤醒/听取**：提示音和明显状态指示；VAD 分句，ASR 转写，文字进入 Agent。
4. **处理**：首版每次只处理一个请求，避免并行语音引发重复动作；等待期间显示忙碌，不缓存额外语音指令。
5. **播报**：播放音频期间暂停唤醒和指令识别，丢弃播放期间录音，不在结束后回放识别该缓冲；结束后回到听取状态。
6. **对话退出**：回复结束后 20 秒无新语音，或收到“没事了”等明确退出指令，清除待处理澄清/动作目标并回到待机。处理和播放耗时不计入用户等待窗口；无音频回复时从显示回复后开始计时。

播报尾音设置可调保护间隔并实测，防止把扬声器输出识别为新指令。首版不支持插话打断；保留停止播放和静音按钮。

唤醒后也不能认为所有声音都是指令；明显闲聊不操作，模糊内容结合上下文追问。电视复现唤醒词仍可能激活系统，不宣称彻底解决误唤醒。

唤醒短语须在兼容性与实录测试后选择；“小屋小屋”为讨论示例，不承诺未经测试即采用。

## 7. Agent 决策与工具契约

### 目标选择
明确指定的房间/设备优先；按人通知时查询目标人物位置；没有明确目标时才使用来源房间。近期目标仅在同一会话且没有歧义时用于“再低一度”等承接。

### 工具集合
- 查询房间状态。
- 查询人物位置。
- 查询设备状态。
- 设置灯光。
- 设置空调。
- 房间播报。

查询返回结构化对象与状态版本；写操作使用稳定对象 ID，不信任模型给出的任意路径、代码或未知设备名。写请求携带由本地编排层生成并在重试时复用的唯一操作 ID。操作结果查询由编排层通过本地状态接口完成，不增加模型可自由选择的控制工具。服务端校验类型、范围、房间归属、在线状态、许可与前置版本。状态已变时返回冲突，让 Agent 重新查询，不直接覆盖。

低风险且目标明确的灯光/空调调整、用户要求的定向通知可直接执行；身份/目标含糊、超范围请求必须澄清或拒绝。

播报内容是纯文本数据，不作为新系统指令、代码或未校验的富文本执行。

### 示例：有点热
定位来源房间，查室温与空调，依据本地默认舒适策略和允许范围决定有限调整；目标不明则询问。解释实际改变，不声称推测的个人偏好是已知事实。

### 示例：叫爸爸和孩子吃饭
查两人模拟位置，按房间去重。已知位置的目标可通知，位置未知的目标说明未通知并询问；不自动全屋广播。不同房间任务由单一播放队列串行播放，Unity 高亮对应房间。

播报工具区分排队、播放中、已播放、失败。只有音频播放完成回执后可说“已在卧室播报”；仅排队时只能说“已安排播报”。不能说“对方听到了/来了”。

## 8. 一致性、故障与隐私

- Unity 初次连接与重连获取完整快照，后续按版本同步增量；发现缺失版本则重新拉取。
- 网络超时不等于操作失败。相同操作 ID 查询/返回已有结果，不能生成新 ID 盲目重试。
- 模拟设备离线返回失败，不修改设备状态。
- 多工具部分成功分别报告，不假装原子成功，不默认撤销已完成动作。
- LLM 超时停止本轮编排，查询已提交操作结果再报告；不继续产生猜测动作。
- TTS 失败保留文字；设备操作不重复执行。定向通知若音频失败，则该播报任务失败。
- 播报状态不确定时先查结果；服务重启后不自动重播未确认任务。
- 默认不持久保存原始音频和视频；内存缓冲使用后释放。角色配置、设备配置和状态可本地保存，临时视觉绑定不跨进程重启保留。
- 为去重/恢复保存最小操作状态；调试转写与执行记录提供清除入口，清除在无在途操作时执行。
- 云端只接收转写和任务必要状态，仍可能包含家庭信息；不宣称使用本地 ASR 就代表全部数据不出本机。
- 密钥保存在本地服务配置，不打包进 Unity、不进入日志或版本库；本地接口默认绑定 loopback，不开放局域网。
- 请求数、超时、工具轮数和播放队列长度均设有限上限，超限明确失败，不无限运行。

## 9. Unity 界面

固定全屋简化 3D 俯视/斜俯视；旁侧包含：
- 语音区：监听/录音/处理/播报状态，转写，回复，静音、按钮唤醒、文字输入与停止播放。
- 测试上下文：当前说话者、模拟收音房间、模拟室温、人物拖动与位置未知设置、设备离线开关。
- 摄像头区：检测框、手动绑定、轨迹丢失提示；可关闭摄像头。
- 执行记录：查询摘要、工具名、参数、目标与结果，不展示或索取模型私有思考链。

不再启动或使用浏览器视觉辅助；后续设计审阅采用文字文档。

## 10. 测试与验收

### 自动化边界
- 状态/策略单测：目标解析、房间去重、范围校验、版本冲突、操作去重。
- 会话单测：唤醒、20 秒超时、退出、澄清承接、播放期间禁识别。
- 集成测试：Unity 连接适配、状态快照/增量/重连、模型服务失败、播报回执；外部模型用可控替身测试程序逻辑，另做真实模型验证。
- 故障测试：离线、超时发生在提交前/后、TTS 失败、重复请求和服务重启。

### 必须通过的场景
1. “打开客厅灯”只改变指定设备，Unity 与权威状态一致。
2. “有点热”查正确房间状态后有限调整或追问。
3. 跨房间找人通知；同房间去重，不同房间依次播报。
4. 移动人物后同一请求使用新位置。
5. 澄清“哪个房间？”→“卧室”完成原请求；同会话“再低一度”目标明确时可承接，退出后不沿用。
6. 设备离线、人物位置未知、云端失败不假报成功。
7. 唤醒后可连续两轮交流，超时/退出后再次操作需要唤醒。
8. 播报不自触发；保护间隔后的正常讲话可识别。
9. 普通闲聊、环境噪声与电视负例记录误唤醒/误操作，不以一次成功演示代替测试。
10. 手动视觉绑定在轨迹丢失后解除，摄像头观察不会改写模拟房间。

### 实机测量与放行条件
使用用户麦克风、单人近距离普通话作为首版支持条件。实录至少 30 条任务语句，包含否定、人名、房间、数字和模糊意图；关键人物/房间/否定/数值信息正确至少 27 条，错误不得被掩盖为工具成功。准备至少 20 条家居 TTS 文本，试听关键字段读音与可理解性。

至少测试 20 次主动唤醒，其中至少 18 次成功进入对话；测试一次 30 分钟无意图音频负例、10 次播报回听；报告唤醒成功率、误唤醒次数、误操作次数和自触发次数。有限负例测试不得出现设备误操作或播报自触发，但通过不构成任意环境零误触发保证。

Unity 与本地 ASR/TTS/检测并行运行至少 30 分钟；记录 RAM/VRAM 峰值、帧率、识别耗时、TTS 首次出声和端到端延迟（含冷启动/热启动）。不得崩溃或显存耗尽。Unity 场景以目标电脑 1080p 至少 30 FPS 为首轮工程目标。云端延迟单独报告，不在未测试前承诺固定秒数；根据测量由用户确认等待是否可接受。

上述量化门槛作为本文验收基线随设计一同获批。模型版本、线程数等以实测调优，但不能通过删除失败用例冒充验收通过。
