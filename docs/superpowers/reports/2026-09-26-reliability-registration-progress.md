# 2026-09-26 可靠性与注册反馈进展

对应路线图：`plans/2026-09-25-project-roadmap.md` 的 P0-1、P0-2。

## 基线与目标

本次修改前只读查询本机运行实例：home 在线、vision HTTP 在线但处于 `idle`、voice 未连接、console 在线。旧终端能看出 voice 未连接，却没有最后一帧时间，也没有后端最后成功响应时间；启动脚本遇到任一服务失败会在启动 console 前退出。

目标是让单项服务故障不遮住终端，同时区分 HTTP 在线、模型就绪、摄像头实际出帧；注册工作区显示当前摄像头的真实画面规格和失败原因分布。

## 已实现

- 启动器逐项报告失败，并在 console 可用时继续打开终端窗口。脚本保留逐服务健康等待，最终汇总故障数。
- vision `/health` 报告模型、模式、错误码、摄像头、最近帧时间及实际画面规格。实际宽高来自收到的帧；帧率是最近最多 30 帧的滚动测量。切换画面源时清除旧规格。
- 终端 `/api/status` 把正在监控却尚未出帧、以及超过 5 秒未出新帧分别标为需要处理；断线时保留本次终端进程内的后端最后响应时间。空闲摄像头明确显示“服务在线 · 摄像头未开启”。
- 注册会话只在内存中按原因累计未通过帧数；注册页显示实际画面规格与原因计数，保留已有的步骤、合格样本与成功提示。未保存图像、生物特征或原始失败帧。

## 验证与边界

- vision 单元测试：66 通过，14 个子测试通过；只使用合成帧/假对象，没有打开摄像头。
- console 单元测试：10 通过；前端 `npm run build` 成功。
- PowerShell 启动脚本 AST 解析无语法错误；`git diff --check` 无空白错误。
- **未验证**四服务完整停止与重启、实际摄像头帧率/画质、真人注册完成及失败分布。修改时本机已有 home/vision/console 进程，因此这些进程仍需重启才能加载新的 Python 状态接口。终端前端构建产物已更新，页面刷新可读取新界面，但旧 Python 进程不能提供新增字段。
- P0-1/P0-2 继续保持“进行中”。应由用户在方便时手动完成四服务停启和真实摄像头注册验收，再根据采集的分布决定是否调整阈值。
